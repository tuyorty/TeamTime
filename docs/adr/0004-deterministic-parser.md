# ADR 0004. Детерминированный парсер как чистая функция

- Статус: принято
- Дата: 2026-10-26

## Контекст

Сообщения шаблонные, но пишут их люди: разный регистр, разные тире, лишние пробелы, свободный текст вместо времени. LLM в проекте запрещён, и результат должен быть воспроизводимым.

## Решение

- `parse_schedule(text, sent_at, tz)` и `parse_daily(text, sent_at, tz)` — чистые функции. Они возвращают `ParseResult(kind, status, data, issues)` и не обращаются к сети, базе и часам.
- Разбор построчный: каждая строка классифицируется (заголовок, имя, день, интервалы, эффективность, буллет, хэштег, пусто, мусор). Затем результат собирается с проверкой обязательных частей.
- У каждой проблемы есть код, уровень (`info`, `warning`, `error`), номер строки и текст на русском. Статус выводится из уровней: есть `error` → `failed`, есть `warning` → `partial`, иначе `ok`.
- Парсер не угадывает. Свободный текст в строке дня («по вайбу с 16:30») сохраняется заметкой с флагом «в заметке есть время», а план по времени остаётся пустым.
- У результата есть `PARSER_VERSION`, чтобы после изменений можно было массово переразобрать сообщения.

## Последствия

- Тесты табличные и быстрые: сотни кейсов за доли секунды.
- Определять тип сообщения (расписание или дейлик) — тоже задача парсера (`detect_kind`). Привязка темы — более сильный сигнал, хэштег — запасной.
- Расширение под LLM (дорожная карта) — отдельный слой поверх, который может предложить исправление для `failed`, но не заменяет детерминированный разбор.
