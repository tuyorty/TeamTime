# xTime v1.4.0

## Изменения после v1.3.0

- Новый раздел «Финансы»: выбор месяца, общие суммы команды и расчёт оплаты по каждому сотруднику.
- Оклад = полная месячная норма × часовая ставка. При недоработке оклад сохраняется. Переработка оплачивается по той же ставке: `max(0, зачтённые часы − норма) × ставка`.
- Зачтённые часы берутся из существующего месячного расчёта после эффективности и штрафа за опоздания. Нормы и ставки — из условий выбранного месяца.
- Администратор добавляет проектные премии с суммой, названием проекта и комментарием. Премию можно изменить или отменить с причиной. Отменённая запись остаётся в истории, но не входит в сумму.
- Повтор запроса на создание не дублирует премию. Одновременные изменения защищены проверкой версии; все правки записываются в журнал.
- Расшифровка сотрудника показывает оклад, часы, переработку и проектные премии. Есть поиск, отборы и экспорт Excel/CSV; в Excel можно выгрузить текущий отбор.
- Интерфейс адаптирован для телефона и обеих тем оформления. В новой демо-базе есть три вымышленные премии за проекты.

Например, норма 160 ч и ставка 500 ₽/ч дают оклад 80 000 ₽ как при 140, так и при 160 зачтённых часах. При 170 ч добавляется 5 000 ₽ за переработку. Проектная премия 10 000 ₽ увеличивает итог до 95 000 ₽.

Раздел показывает расчёт сумм. Фактические перечисления, авансы и налоговые расчёты не учитываются. Кадровые даты приёма и увольнения не ведутся; пропорциональный оклад за неполный месяц автоматически не рассчитывается.

## Файлы обновления

- `xtime-v1.4.0.tar.gz` — автономный архив с образами приложения и PostgreSQL для Linux amd64.
- `xtime-v1.4.0.tar.gz.sha256` — контрольная сумма.
- В архиве: `images.tar.gz`, установщик, серверный Compose, шаблон настроек, `VERSION`, `README.md` и эта инструкция под именем `UPDATE.md`.

Рабочий `.env` и данные сотрудников в архив не входят. На сервер переносятся только архив и файл контрольной суммы. Локальные `.env` и `compose.demo.yml` переносить не нужно.

## Копирование

Из корня проекта в PowerShell, заменив `user@server` своим SSH-адресом:

```powershell
scp dist/xtime-v1.4.0.tar.gz dist/xtime-v1.4.0.tar.gz.sha256 user@server:/tmp/
ssh user@server
```

## Установка

На сервере:

```bash
cd /tmp
sha256sum -c xtime-v1.4.0.tar.gz.sha256 &&
sudo /opt/xtime/backup.sh &&
tar -xzf xtime-v1.4.0.tar.gz &&
sudo ./xtime-v1.4.0/install.sh /opt/xtime
```

Установка продолжится только после успешной проверки архива и резервного копирования. Если в рабочем `.env` задан `XTIME_TAG` с конкретной старой версией, перед установкой измените его на `v1.4.0`; пустое значение или `current` менять не требуется.

Миграция **`a3b6c7d8e9f0`** после `f2a5b6c7d8e9` применяется автоматически. Она добавляет таблицу проектных премий `project_bonuses`. Существующие сообщения, нормы, ставки и факты не переписываются. Переразбор сообщений не требуется. В рабочей базе проектные премии сначала пустые — администратор добавляет их сам.

База остаётся в прежнем Docker-томе `pgdata` проекта `xtime`; данные никуда не переносятся. Рабочий `.env` и настройки SSH-туннеля сохраняются. Если v1.3.0 ещё не установлен, можно обновиться сразу до v1.4.0: все недостающие миграции применятся по порядку, а предыдущие функции входят в этот архив.

Сохраните предыдущий архив и резервную копию до проверки обновления. Откат на предыдущую версию со старой схемой БД нужно выполнять вместе с восстановлением соответствующей резервной копии; удалять том базы для обновления не нужно.

## Проверка после установки

```bash
cd /opt/xtime
sudo docker compose ps
sudo docker compose exec -T api python -c 'import teamtime; print(teamtime.__version__)'
sudo docker compose exec -T api alembic current
sudo docker compose logs --tail=80 api bot
```

Ожидаемые значения: версия **`v1.4.0`**, миграция **`a3b6c7d8e9f0`**. API, сайт и база — healthy; бот — запущен при настроенном подключении к Telegram. Обновите вкладку сайта через Ctrl+F5.

1. Откройте **Финансы** в боковой панели (на телефоне — «Ещё → Финансы»), выберите месяц. Сверху указаны суммы всей команды, под таблицей — суммы текущего отбора.
2. Откройте сотрудника. Проверьте оклад по норме и ставке; переработка должна совпадать с расчётом во вкладке месяца. При недоработке оклад остаётся полным.
3. В режиме администратора проверьте кнопку **Добавить премию**. Для реального начисления укажите сотрудника, проект и сумму; месяц указан в форме. Сохранённая премия сразу добавится в итог.
4. Откройте **Экспорт → Вся команда · Excel**. В файле должны быть листы «Расчёт оплаты», «Проектные премии» и «Правила».
5. Исправления и отмены премий доступны в расшифровке сотрудника; история — в **Админка → Журнал правок**. Тестовое создание и отмену удобнее проверять на отдельном демо-стенде, чтобы не добавлять фиктивные начисления в рабочую базу.
