# xTime v1.7.2

## Исправления после v1.7.1

- При нескольких фактических отрезках опоздание считается по приходу к плановой смене.
  Раньше использовался первый написанный отрезок: ночная подработка перед дневным отчётом
  могла как завышать штраф, так и скрывать дневное опоздание.
- Выбирается самый ранний фактический отрезок, пересекающийся с любым плановым. Если
  пересечений нет — первый отрезок после начала смены; если вся работа закончилась до
  начала смены, положительного опоздания нет. Порядок строк дейлика не влияет на выбор.
- Например, план 14:00–17:00, факт 03:00–05:30 и 14:05–18:00 даёт 5 минут опоздания.
  План 11:00–18:00, факт 22:00–00:00 и 11:40–16:40 даёт 40 минут вместо 11 часов.
- Таблицы дня и недели, список опозданий месяца, профиль, графики прихода и Excel
  показывают то же время прихода, которое использовано при расчёте штрафа.
- Исходный порядок и длительности интервалов, даты дейликов, эффективность, привязки
  сотрудников, нормы и ставки сохраняются. Меняются опоздания, штрафы, итог и производная
  от итога переработка. В отдельных месяцах штраф может как уменьшиться, так и увеличиться.

Новых миграций нет. Версия парсера остаётся **4**, ревизия БД — **c5d8e9f0a1b2**.
Отчёты за прошлые месяцы пересчитываются при чтении; повторный импорт или массовый
переразбор для этого исправления не требуется.

## Обновление сервера

Архив для **Linux amd64** и контрольная сумма находятся в `D:\xTimeReleases\v1.7.2`.
В PowerShell замените SSH-адрес своим:

```powershell
$xtimeServer = "user@server"
scp D:/xTimeReleases/v1.7.2/xtime-v1.7.2.tar.gz D:/xTimeReleases/v1.7.2/xtime-v1.7.2.tar.gz.sha256 "${xtimeServer}:/tmp/"
ssh $xtimeServer
```

На сервере с установкой в `/opt/xtime`:

```bash
cd /tmp &&
sha256sum -c xtime-v1.7.2.tar.gz.sha256 &&
sudo /opt/xtime/backup.sh &&
sudo cp -p /opt/xtime/.env /opt/xtime/backups/env-before-v1.7.2 &&
tar -xzf xtime-v1.7.2.tar.gz &&
sudo sed -i 's/^XTIME_TAG=.*/XTIME_TAG=v1.7.2/' /opt/xtime/.env &&
sudo ./xtime-v1.7.2/install.sh /opt/xtime
```

При отсутствии `XTIME_TAG` используются загруженные образы `current`.
Рабочий `.env`, база и исходные данные сверки в архив не входят.

## Проверка

```bash
cd /opt/xtime
sudo docker compose ps
sudo docker compose exec -T api python -c 'import teamtime; from teamtime.parsing import PARSER_VERSION; print(teamtime.__version__, PARSER_VERSION)'
sudo docker compose exec -T api alembic current
```

Ожидается **`v1.7.2 4`**, ревизия **`c5d8e9f0a1b2`**. API, сайт и база — healthy.
Обновите страницу и проверьте детализацию опозданий за нужный месяц. В Excel на листах
«Дни» и «Опоздания» должен совпадать выбранный приход к смене. Отработанные и эффективные
часы сравните с выгрузкой до обновления. Резервную копию до обновления и архив v1.7.1
сохраните для отката.
