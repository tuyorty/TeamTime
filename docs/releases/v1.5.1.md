# xTime v1.5.1

## Изменения после v1.5.0

Расписание теперь проверяется относительно даты исходного сообщения в часовом поясе команды:

- Текущая и следующая недели принимаются как обычно.
- Прошедшая неделя или более далёкая будущая дают предупреждение `suspicious_sprint_week`. Сообщение попадает в инбокс, бот ставит настроенную предупреждающую реакцию (по умолчанию **🤔**) и объясняет несоответствие дат.
- В предупреждении видны дата отправки и неделя, к которой привязалось расписание. Автору предлагается проверить месяц и год в заголовке.
- При исправлении исходного сообщения предупреждение снимается. Если даты указаны намеренно, администратор может подтвердить их в инбоксе.

Например, заголовок `Спринт 02.10 - 08.10`, отправленный 31.10.2026, относится к неделе 28.09–04.10.2026 и теперь вызывает предупреждение. Заголовок `Спринт 02.11 - 08.11` в тот же день принимается без него.

Проверка не исправляет месяц или год автоматически и не переносит расписание на предполагаемую неделю. Импорт истории и переразбор используют дату исходного сообщения, а не текущую дату сервера. Версия парсера повышена до **3**.

## Файлы обновления

- `xtime-v1.5.1.tar.gz` — автономный архив с образами приложения и PostgreSQL для **Linux amd64**.
- `xtime-v1.5.1.tar.gz.sha256` — контрольная сумма.
- В архив входят `images.tar.gz`, установщик, серверный Compose, шаблон настроек, `VERSION`, `README.md` и эта инструкция под именем `UPDATE.md`.

Рабочий `.env`, локальный `compose.demo.yml` и данные сотрудников переносить не нужно: в архив они не входят.

## Копирование и установка

Из корня проекта в PowerShell, заменив `user@server` своим SSH-адресом:

```powershell
scp dist/xtime-v1.5.1.tar.gz dist/xtime-v1.5.1.tar.gz.sha256 user@server:/tmp/
ssh user@server
```

Если в серверном `.env` параметр `XTIME_TAG` закреплён на конкретной старой версии, перед установкой измените его на `v1.5.1`. Пустое значение или `current` менять не требуется.

На сервере:

```bash
cd /tmp
sha256sum -c xtime-v1.5.1.tar.gz.sha256 &&
sudo /opt/xtime/backup.sh &&
tar -xzf xtime-v1.5.1.tar.gz &&
sudo ./xtime-v1.5.1/install.sh /opt/xtime
```

Установка продолжится только после успешной проверки архива и резервного копирования. При обновлении с v1.5.0 новых миграций нет; ревизия БД остаётся **`a3b6c7d8e9f0`**. При обновлении с более ранней версии недостающие миграции применяются автоматически.

База остаётся в существующем томе `pgdata` проекта `xtime`, рабочие настройки и SSH-туннель сохраняются. ТВ-экран и настройка чередования вкладок повторной настройки не требуют. Предыдущий архив и резервную копию сохраните до проверки обновления.

## Проверка после установки

```bash
cd /opt/xtime
sudo docker compose ps
sudo docker compose exec -T api python -c 'import teamtime; from teamtime.parsing import PARSER_VERSION; print(teamtime.__version__, PARSER_VERSION)'
sudo docker compose exec -T api alembic current
sudo docker compose logs --tail=80 api bot
```

Ожидаемые значения: **`v1.5.1 3`**, миграция **`a3b6c7d8e9f0`**. API, сайт и база — healthy; бот — запущен при настроенном подключении к Telegram.

Проверка дат работает при получении нового сообщения, его правке или индивидуальном переразборе. Уже принятые сообщения при установке автоматически не пересчитываются. Кнопка инбокса «Переразобрать всё» обрабатывает только записи, ожидающие решения; она не проверяет всю принятую историю. В старом ошибочном сообщении исправьте заголовок на нужный месяц — бот обработает правку и отзовёт производные версии этого сообщения с ошибочными датами.

Для ручной проверки предупреждения используйте демо-эмулятор: отправьте вымышленное расписание за прошлый месяц и откройте инбокс. В рабочую группу тестовые расписания отправлять не нужно.

## Проверки перед выпуском

Пройдены **549 тестов бэкенда**, линтер, проверка форматирования и типов. Проверены ошибки в месяце и году, границы недель в часовом поясе команды, переход года, предупреждение и исправление через поддельный Telegram, отсутствие повторных ответов, инбокс, подтверждение администратором и переразбор истории.

Фронтенд и скриншоты совпадают с v1.5.0. При выпуске проверяются собранные образы, версия приложения и парсера, запуск API и сайта на отдельной демобазе, ревизия БД и состав архива. Настоящий Telegram-бот локально не запускается.
