# xTime v1.4.1

## Изменения после v1.4.0

- В финансах появились графики состава начислений и сумм по сотрудникам. Есть разбивка на оклады, переработки и проектные премии, режим «Только доплаты» и переход к расчёту сотрудника по нажатию.
- Графики учитывают выбранный месяц и отбор сотрудников; порядок соответствует сортировке таблицы. Длинный список прокручивается внутри карточки.
- Исправлено обрезание круговой диаграммы: радиус зависит от доступного размера, по краям оставлен запас. Проверено на широком экране и телефонах.
- В финансах и во вкладке «Месяц → Премии» добавлен явный выбор сортировки от большего к меньшему и обратно, по фамилии и другим показателям. Заголовки таблиц синхронизированы со списком сортировки.
- В проектных премиях доступны поиск по проекту, сотруднику и комментарию, сортировка по сумме, названию, фамилии и времени добавления.
- Из фактов недели и месяца убраны «Работа в выходные по календарю» и «Самая длинная серия дней с работой».

Формулы оплаты, настройки бота и схема БД относительно v1.4.0 не изменились. Финансы по-прежнему показывают расчёт сумм, без отметок фактических выплат.

## Файлы обновления

- `xtime-v1.4.1.tar.gz` — автономный архив с образами приложения и PostgreSQL для Linux amd64.
- `xtime-v1.4.1.tar.gz.sha256` — контрольная сумма.
- В архиве: `images.tar.gz`, установщик, серверный Compose, шаблон настроек, `VERSION`, `README.md` и эта инструкция под именем `UPDATE.md`.

Рабочий `.env` и данные сотрудников в архив не входят. На сервер переносятся только архив и контрольная сумма. Локальные `.env` и `compose.demo.yml` переносить не нужно.

## Копирование

Из корня проекта в PowerShell, заменив `user@server` своим SSH-адресом:

```powershell
scp dist/xtime-v1.4.1.tar.gz dist/xtime-v1.4.1.tar.gz.sha256 user@server:/tmp/
ssh user@server
```

## Установка

На сервере:

```bash
cd /tmp
sha256sum -c xtime-v1.4.1.tar.gz.sha256 &&
sudo /opt/xtime/backup.sh &&
tar -xzf xtime-v1.4.1.tar.gz &&
sudo ./xtime-v1.4.1/install.sh /opt/xtime
```

Установка продолжится только после успешной проверки архива и резервного копирования. Если в рабочем `.env` задан `XTIME_TAG` с конкретной старой версией, перед установкой измените его на `v1.4.1`; пустое значение или `current` менять не требуется.

При обновлении с v1.4.0 новых миграций нет. Ожидаемая ревизия БД остаётся **`a3b6c7d8e9f0`**. Переразбор сообщений не требуется. Если установлена более ранняя версия, недостающие миграции применятся автоматически по порядку; предыдущие функции входят в этот архив.

База остаётся в прежнем Docker-томе `pgdata` проекта `xtime`; данные никуда не переносятся. Рабочий `.env` и настройки SSH-туннеля сохраняются. Сохраните предыдущий архив и резервную копию до проверки обновления.

## Проверка после установки

```bash
cd /opt/xtime
sudo docker compose ps
sudo docker compose exec -T api python -c 'import teamtime; print(teamtime.__version__)'
sudo docker compose exec -T api alembic current
sudo docker compose logs --tail=80 api bot
```

Ожидаемые значения: версия **`v1.4.1`**, миграция **`a3b6c7d8e9f0`**. API, сайт и база — healthy; бот — запущен при настроенном подключении к Telegram. Обновите вкладку сайта через Ctrl+F5.

1. Откройте **Финансы** и выберите «Итого: больше → меньше». Порядок сотрудников в таблице и на графике должен совпасть.
2. Переключите график в режим **Только доплаты**, выберите сотрудника поиском и нажмите его полосу. Откроется подробный расчёт. Круговая диаграмма целиком помещается в карточке.
3. В блоке **Премии за проекты** проверьте поиск и сортировку по сумме. Во вкладке **Месяц → Премии** также доступен отдельный список сортировки.
4. В **Фактах недели** и **Фактах месяца** больше нет работы в выходные по календарю и самой длинной серии дней с работой.

## Проверки перед выпуском

Пройдены 51 тест фронтенда, 27 браузерных сценариев, линтер, проверка типов, контраст тем и сборка. Скриншоты обновлены для светлой и тёмной тем, компьютера и телефона. Проверены границы круговой диаграммы на ширинах 320, 390 и 1440 px.

Код бэкенда и миграции совпадают с v1.4.0; его 529 тестов были пройдены при предыдущем выпуске. В этом обновлении повторно проверяется запуск собранных образов, версия приложения и текущая ревизия БД.
