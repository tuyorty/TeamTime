# xTime v1.6.0

## Изменения после v1.5.1

- Сотрудники на экранах «Сегодня», недели, планов и телевизора отображаются по алфавиту. Выбранная пользователем сортировка отчётов сохраняется.
- ТВ-экран использует высоту окна: сводка «Вся команда» и компактный блок «Дальше по расписанию» находятся справа. Блок «Завтра» убран. Большая команда автоматически делится на страницы; 20 сотрудников помещаются в Full HD на одной странице.
- Текущее время отмечено одной заметной красной линией через все строки сотрудников на экранах «Сегодня» и телевизора.
- В «Пульсе недели» подпись уточнена: «Всего за неделю: план …, факт …».
- Исправлено падение страницы из-за аватара сообщения с ещё не привязанным автором.
- Поддержаны лабораторные расписания с выделенными заголовками, диапазоном `ПН — ВС: отпуск` и несколькими интервалами работы. Три и более интервалов поддерживаются в расписании, дейликах и отображении.
- Подключение отдельной беседы лаборатории использует того же бота и общую доску. Название темы «виклики» распознаётся при импорте, команда `/bind виклики` привязывает расписания. Инструкция — `MULTIPLE_CHATS.md` в архиве.
- Добавлен статус **Командировка** на день или период. Администратор ставит его в карточке дня; заявки сотрудников требуют согласования. Дейлики остаются в истории, но часы командировки исключаются из зачёта, опозданий, переработки и сумм команды.
- Отпуск и командировка уменьшают норму для зачёта пропорционально рабочим дням месяца по календарю xTime. **Оклад сохраняется от полной договорной нормы.** Пример: 80 часов, 20 рабочих дней, 10 дней отпуска → норма 40 часов, оклад от 80 часов. Больничные и отгулы норму не меняют. В отчётах, финансах, боте и выгрузках видны пересчитанные значения; подробности — `FINANCE.md`.

**Пересчёт прошлых месяцев:** правило снижения нормы применяется и к ранее внесённым отпускам, включая явную отметку «отпуск» в расписании. Норма, выполнение нормы и переработка могут измениться; договорная норма и оклад сохраняются. Автоматического изменения выплат или отправки сообщений сотрудникам нет.

Рабочие дни определяются настройками выходных и праздников выбранного месяца. По умолчанию выходной — воскресенье; если в компании пятидневная неделя, проверьте настройки календаря. В месяце с другим числом рабочих дней снижение за две недели будет отличаться от половины нормы.

## Файлы обновления

- `xtime-v1.6.0.tar.gz` — автономный архив для **Linux amd64** с образами приложения и PostgreSQL.
- `xtime-v1.6.0.tar.gz.sha256` — контрольная сумма.
- В архиве: `images.tar.gz`, установщик, серверный Compose, `.env.example`, `VERSION`, `README.md`, `UPDATE.md`, `MULTIPLE_CHATS.md`, `FINANCE.md`.

Рабочий `.env`, база, данные сотрудников, контексты агентов и локальное демо в архив не входят.

## Установка на существующий сервер

Скопируйте архив и контрольную сумму на сервер. Например, в PowerShell, заменив SSH-адрес:

```powershell
scp D:/xTimeReleases/v1.6.0/xtime-v1.6.0.tar.gz D:/xTimeReleases/v1.6.0/xtime-v1.6.0.tar.gz.sha256 user@server:/tmp/
ssh user@server
```

Если в серверном `.env` `XTIME_TAG` закреплён на старой версии, измените его на `v1.6.0`. Значение `current` или отсутствие переменной менять не требуется. Остальные действующие настройки сохраните.

На сервере:

```bash
cd /tmp
sha256sum -c xtime-v1.6.0.tar.gz.sha256 &&
sudo /opt/xtime/backup.sh &&
tar -xzf xtime-v1.6.0.tar.gz &&
sudo ./xtime-v1.6.0/install.sh /opt/xtime
```

При обновлении автоматически применяется миграция **`b4c7d8e9f0a1`**: в перечисление статусов PostgreSQL добавляется `business_trip`. Дейлики и расписания не удаляются. База остаётся в существующем томе проекта `xtime`; рабочие настройки и SSH-туннель сохраняются.

## Проверка после обновления

```bash
cd /opt/xtime
sudo docker compose ps
sudo docker compose exec -T api python -c 'import teamtime; from teamtime.parsing import PARSER_VERSION; print(teamtime.__version__, PARSER_VERSION)'
sudo docker compose exec -T api alembic current
sudo docker compose logs --tail=80 api bot
```

Ожидается **`v1.6.0 4`**, миграция **`b4c7d8e9f0a1`**. API, сайт и база — healthy; бот запущен, если настроено подключение к Telegram.

Проверьте таблицу месяца и расшифровку финансов сотрудника с отпуском: договорная норма для оклада остаётся прежней, а норма для зачёта уменьшается. В карточке дня администратору доступна «Командировка» на день или период. На рабочей базе используйте реальные статусы; проверочные данные создавайте в отдельном демо.

Бот ещё не подключён к лабораторной беседе. После обновления его нужно добавить в беседу, разрешить чат в админке, привязать темы и Telegram-аккаунты сотрудников по `MULTIPLE_CHATS.md`. Сообщения до добавления бота автоматически не появятся: для них нужен импорт истории. Уже принятые расписания автоматически не переразбираются; при необходимости переразберите конкретное сообщение в инбоксе или повторно импортируйте историю.

## Откат

Сохраните предыдущий архив и резервную копию до проверки. Для полного отката после использования нового статуса восстановите **базу из копии до обновления** и предыдущие образы по `README.md`. Одного переключения старого образа недостаточно: предыдущий код не знает статус `business_trip`. `alembic downgrade` намеренно не удаляет значение enum и историю статусов.
