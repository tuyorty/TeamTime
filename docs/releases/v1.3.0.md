# xTime v1.3.0

## Изменения после v1.2.2

- «Сегодня»: просмотр завтрашнего расписания, крупные часы с часовым поясом, переключатели без смещения при смене дня.
- Профиль сотрудника: форматирование и копирование телефона, просмотр фото по нажатию, направления работы, помощь коллегам и ближайшее согласованное отсутствие.
- Рабочая статистика: текущий месяц по умолчанию; сводка, графики, календарь часов и пунктуальность используют выбранный период. Несколько месяцев прокручиваются внутри карточки постоянной высоты.
- «Планы»: проверка наличия расписаний, исходных списков работ, обязательных дней и точных интервалов. В фактах недели и месяца добавлены работа в календарные выходные и поздние часы, длинные дни, серии и изменения расписания.
- Инбокс: заявки на статусы, фильтры дат, сортировка и страницы по 25 сообщений. В демо появился пример согласования через эмулятор.
- История расчётов: нормы, ставки и правила сохраняются с месяцем начала действия. Неактивные сотрудники с данными остаются в исторических отчётах. Экспорт позволяет выбрать всю команду или текущий отбор.
- Бот: `/absent` создаёт заявку для администратора; `/daily` помогает сохранить часы и эффективность; `/check` показывает сохранённый день; `/notifications` задаёт личные напоминания и тихое время.
- Однократный повтор напоминания через 30 минут доступен по кнопке. Сохранены ограничения от повторных отправок при перезапуске и неизвестном результате доставки. Общий выключатель администратора имеет приоритет.
- Реакции на сообщение и его правки обрабатываются последовательно. Добавлена диагностика связи с Telegram, ответов, реакций, напоминаний, доступности лички и резервного копирования.
- Убран мусор из репозитория, локальный демо-конфиг объединён в `compose.demo.yml`.

Исходные списки задач из расписаний и дейликов сохраняются. Нового ручного трекера задач, прогнозов и личной динамики в интерфейсе нет.

## Файлы обновления

- `xtime-v1.3.0.tar.gz` — автономный архив с образами приложения и PostgreSQL для Linux amd64.
- `xtime-v1.3.0.tar.gz.sha256` — контрольная сумма.
- Внутри архива: `images.tar.gz`, установщик, конфигурация сервера, шаблон настроек, `VERSION`, `README.md` и эта инструкция под именем `UPDATE.md`.

Рабочий `.env` и данные сотрудников в архив не входят. Локальные `.env` и `compose.demo.yml` на сервер переносить не нужно.

## Копирование на сервер

Из корня проекта в PowerShell, заменив `user@server` своим SSH-адресом:

```powershell
scp dist/xtime-v1.3.0.tar.gz dist/xtime-v1.3.0.tar.gz.sha256 user@server:/tmp/
ssh user@server
```

## Установка

На сервере:

```bash
cd /tmp
sha256sum -c xtime-v1.3.0.tar.gz.sha256 &&
sudo /opt/xtime/backup.sh &&
tar -xzf xtime-v1.3.0.tar.gz &&
sudo ./xtime-v1.3.0/install.sh /opt/xtime
```

Команды связаны через `&&`: установка продолжится только после успешной проверки архива и резервного копирования.

В выпуске есть миграция **`f2a5b6c7d8e9`** после `e1f4a5b6c7d8`. Установщик применяет её автоматически. Она добавляет историю условий, заявки, личные настройки уведомлений, черновики бота и диагностику. Действующие нормы, ставки и сохранённые правила фиксируются как исходные условия; более ранние изменения, которых не было в базе, восстановить невозможно.

Рабочий `.env`, база и SSH-туннель сохраняются. Переразбор сообщений не требуется. Архив v1.2.2 и резервную копию перед обновлением сохраните до завершения проверки: в этом выпуске изменяется схема БД.

## Проверка после установки

```bash
cd /opt/xtime
sudo docker compose ps
sudo docker compose exec -T api python -c 'import teamtime; print(teamtime.__version__)'
sudo docker compose exec -T api alembic current
sudo docker compose logs --tail=80 api bot
```

Ожидаемые значения: версия `v1.3.0`, миграция `f2a5b6c7d8e9`. API, сайт и база должны быть healthy, бот — работать. Обновите вкладку сайта, при необходимости через Ctrl+F5.

1. В «Сегодня» переключите сегодня и завтра, проверьте время и отсутствие смещения кнопок.
2. В профиле выберите месяц и три месяца: все графики должны менять период, календарь — прокручиваться внутри карточки. Проверьте копирование телефона и просмотр фото.
3. В «Админка → Сотрудники / Настройки» проверьте исходную историю условий. Изменение с будущего месяца должно оставлять прежний месяц с его условиями.
4. В личке бота отправьте `/start` или `/help`, чтобы открыть свежее меню. Проверьте `/check` и `/notifications`. Для личной доставки сотрудник должен открыть личку с ботом и иметь привязанный аккаунт.
5. При следующем реальном запросе отсутствия или удалёнки используйте `/absent`. До решения администратора действует прежний статус. Решение находится в «Инбокс → Заявки на статусы»; сотрудник проверяет его кнопкой в ответе бота.
6. Откройте «Админка → Состояние системы». Данные диагностики начинают накапливаться после обновления; отсутствие истории старых доставок ожидаемо. Следующая резервная копия, созданная новым `backup.sh`, появится в диагностике.

Для безопасной проверки согласования на вымышленных данных используйте отдельный локальный демо-стенд: «Эмулятор чата → Проверка согласования статуса». На рабочем сервере эта форма недоступна.
