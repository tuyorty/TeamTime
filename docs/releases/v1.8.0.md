# xTime v1.8.0

## Что изменилось после v1.7.2

- Расписание не исчезает из-за ошибки в очередной правке. Новые задачи показываются
  независимо от согласования поздних изменений часов. Игнорирование отклоняет выбранную
  версию и восстанавливает предыдущую пригодную, а не удаляет всю неделю.
- В **Планы → Что менялось** и из инбокса доступна история часов, задач и исходных
  сообщений. Время отправки или редактирования отделено от времени обработки.
  **Все версии сообщения** показывает также тексты с ошибкой разбора. История содержит
  только версии, которые получил xTime: пропущенные Telegram-обновления восстановить нельзя.
- Администратор может подтвердить **невыход** в карточке дня или инбоксе, указав причину.
  Только после завершения всей смены её часы без перерывов попадают в сумму опозданий;
  далее один раз применяется месячная шкала. Отсутствие дейлика само по себе не штрафуется.
  Снимок часов сохраняется при правках плана. Отмена требует причины; поздний дейлик,
  согласованное отсутствие или праздник приостанавливают начисление невыхода.
  Неоднозначные и пересекающиеся интервалы сначала нужно исправить.
- В инбоксе сравнивается отправленная версия, а не её ручной клон. Более поздний ручной
  план имеет приоритет; интерфейс объясняет, когда одобрение старой правки не меняет часы.
- Теги **#виклик**, **#виклики**, **#викли**, **#weekly** исключены из обработки:
  бот не требует дейлик, не отвечает и не ставит реакцию на такие сообщения.
- Бот проверяет соответствие отправителя и сотрудника в расписании. Добавлено личное
  напоминание за час до смены с настройками и защитой от повторов при сбоях.
- Итоги финансов следуют выбранному отделу и поиску. Линия текущего времени на экранах
  команды получила подпись; локальный демо-стенд содержит два вымышленных отдела.
- **Обычные финансы работают по умолчанию. Фонд остаётся в разработке:** интерфейс,
  API, команды, подтверждения и напоминания фонда выключены, даже при старом флаге в БД.
  Его данные сохранены. Ранее отдельно включённая именная защита доступа сохраняется;
  обычные команды бота продолжают работать. Новая установка её не активирует.
- Сохранены наработки фонда и инструменты зашифрованного резервного копирования.
  Таймер и отправка копий сами не включаются. Реальная история, спорные часы и правила
  фонда остаются отдельной незавершённой работой: [статус](../fund-verification.md).
- Установщик использует точный тег пакета вместо старого `XTIME_TAG`, проверяет версию
  работающего API и только после успеха обновляет `VERSION`. Старые образы не удаляются.
- API подтверждает сохранение только после успешного завершения транзакции БД:
  следующий запрос сразу видит новую запись, ошибка сохранения не выдаётся за успех.

Обычная формула оплаты сохраняется: полный оклад по норме и ставке, переработка по той
же ставке и проектные премии. Штрафное время влияет на переработку, а не снижает оклад.

## Данные и миграции

Версия парсера — **5**, конечная ревизия БД — **b0c3d4e5f6a7**.
После v1.7.2 применяются пять миграций: напоминания о начале смены, три миграции
неактивного фонда и таблица подтверждённых невыходов. Существующие сообщения, планы,
дейлики, условия, премии и настройки не заменяются демо-данными. Поле эффективности
интервала добавляется как необязательное; прежняя эффективность дейлика сохраняет действие.

## Обновление

Архив **Linux amd64** и контрольная сумма: `D:\xTimeReleases\v1.8.0`.
В PowerShell подставьте свой SSH-адрес:

```powershell
$xtimeServer = "user@server"
scp D:/xTimeReleases/v1.8.0/xtime-v1.8.0.tar.gz D:/xTimeReleases/v1.8.0/xtime-v1.8.0.tar.gz.sha256 "${xtimeServer}:/tmp/"
ssh $xtimeServer
```

На сервере, если xTime установлен в `/opt/xtime`:

```bash
cd /tmp &&
sha256sum -c xtime-v1.8.0.tar.gz.sha256 &&
sudo /opt/xtime/backup.sh &&
sudo cp -p /opt/xtime/.env /opt/xtime/backups/env-before-v1.8.0 &&
tar -xzf xtime-v1.8.0.tar.gz &&
sudo ./xtime-v1.8.0/install.sh /opt/xtime
```

`XTIME_TAG` менять вручную не нужно. Миграции выполняются при старте API.
Архив не содержит рабочего `.env`, токенов и реальных данных. Сохраните резервную
копию и предыдущий релиз до проверки результата. Не используйте `docker compose down -v`.

## Проверка после установки

```bash
cd /opt/xtime
sudo docker compose ps
sudo docker compose exec -T api teamtime version
sudo docker compose exec -T api alembic current
sudo docker compose logs --since 10m --tail 100 api bot
```

Ожидается **v1.8.0**, ревизия **b0c3d4e5f6a7**. API, web и db — healthy;
bot — running, если проверка Telegram прошла. При недоступном Telegram установщик
оставляет сайт работающим и явно сообщает, что бот не запущен.

1. Обновить страницу браузера, войти администратором. В инбоксе нажать
   **Переразобрать всё** — это переразбор ожидающих решения записей. Для уже закрытых
   сообщений при необходимости выбрать конкретную запись и **Переразобрать**.
   Это не повторная отправка сообщений в Telegram.
2. Проверить нужную неделю: часы и новые задачи, затем **Планы → Что менялось** и
   **Все версии сообщения** в инбоксе.
3. Для фактического невыхода проверить прежний план, подтвердить невыход с причиной,
   затем отклонить позднюю правку выходного. Игнорирование отклоняет всю выбранную
   версию, включая её задачи. Чтобы сохранить новые задачи с прежними часами,
   вручную поправить только спорный день в карточке таблицы.
4. Проверить сумму опозданий и месячный штраф, обычные финансы и отбор отделов.
   Фонд должен оставаться недоступным; новой кнопки фонда в боте быть не должно.
5. Отправить обычный тестовый дейлик в рабочем чате и проверить реакцию, сохранённый
   день и личное меню бота. Доставка Telegram зависит от рабочего туннеля и сети.

При ошибке установки сохранить лог и копию до обновления. Автоматического отката БД
нет: восстановление прежней копии выполняется отдельно после остановки записывающих
сервисов и сохранения новых данных. Повтор установки запускает подготовленный пакет:
`sudo /opt/xtime/install.sh /opt/xtime`.
