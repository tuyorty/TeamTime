# xTime v1.2.2

## Изменения после v1.2.1

- Исправил пропадание реакции при кратком сбое SOCKS-прокси или Telegram. Бот делает до трёх попыток выставить ту же реакцию, с тайм-аутом запроса 15 секунд и паузами 2 и 4 секунды. Ограничения Telegram учитываются: пауза не сокращается, при ожидании больше 30 секунд попытки прекращаются.
- Добавил кнопку «Сотрудники» и команду `/people`: выбор человека, его часы, эффективность, опоздания и задачи за день, неделю или месяц.
- Добавил стрелки для переключения периодов и календарь по кнопке с датой. Выбранный сотрудник сохраняется при смене даты и вида отчёта.
- Добавил `/day` для просмотра другого дня; можно сразу указать `/day 29.10.2026`. В прошлом показываются расписание и факт за выбранную дату, без текущего времени и присутствия «сейчас».
- Привязал итоги дня к выбранной дате. Длинные отчёты и каталог сотрудников разбил на страницы; кнопки обновляют одно сообщение.
- Сохранил проверку доступа на каждом нажатии: в личке данные видят привязанные активные сотрудники, в группе — участники разрешённого чата.

Проверки: 491 тест бэкенда, 42 теста фронтенда, 16 браузерных сценариев,
линтеры и проверка типов. Все 7 сценариев генерации скриншотов прошли;
скриншоты светлой и тёмной тем, компьютера и телефона обновлены.

## Файлы обновления

- `xtime-v1.2.2.tar.gz` — автономный архив с образами приложения и PostgreSQL для Linux amd64.
- `xtime-v1.2.2.tar.gz.sha256` — контрольная сумма архива.
- Внутри архива есть установщик, `VERSION`, `README.md` и эта инструкция под именем `UPDATE.md`.

## Копирование на сервер

Из корня проекта в PowerShell, заменив `user@server` своим SSH-адресом:

```powershell
scp dist/xtime-v1.2.2.tar.gz dist/xtime-v1.2.2.tar.gz.sha256 user@server:/tmp/
ssh user@server
```

## Установка

На сервере:

```bash
cd /tmp
sha256sum -c xtime-v1.2.2.tar.gz.sha256 &&
sudo /opt/xtime/backup.sh &&
tar -xzf xtime-v1.2.2.tar.gz &&
sudo ./xtime-v1.2.2/install.sh /opt/xtime
```

Рабочий `.env`, база, настройки и SSH-туннель остаются на месте.
Локальный демо-файл `.env` переносить не нужно.
Новых миграций после v1.2.1 нет; текущая ревизия остаётся `e1f4a5b6c7d8`.
Установщик применит ранее не установленные миграции автоматически.
Переразбирать сообщения не требуется.

## Проверка после установки

Команды Compose выполняйте из `/opt/xtime`, где находится конфигурация:

```bash
cd /opt/xtime
sudo docker compose ps
sudo docker compose exec -T api python -c 'import teamtime; print(teamtime.__version__)'
sudo docker compose exec -T api alembic current
sudo docker compose logs --tail=80 api bot
```

Ожидаемая версия — `v1.2.2`. API, сайт и база должны быть healthy, бот — работать.

В личке бота:

1. Отправьте `/start` или `/help`, чтобы получить обновлённую клавиатуру.
2. Откройте `/people`, выберите сотрудника и переключите день, неделю и месяц.
3. Откройте `/day`, нажмите стрелку назад и проверьте вчерашнюю дату и её итоги.
4. Нажмите кнопку с датой, выберите другой месяц и день. Дата и сотрудник должны сохраняться при переключении видов отчёта.
5. При следующем обычном дейлике проверьте реакцию. При кратком сбое в логе появится `bot.reaction_retry`, после успешного повтора — `bot.reaction_recovered`; после исчерпания попыток — `bot.reaction_abandoned`.

Старые сообщения и клавиатуры Telegram сохраняют прежний вид: для новой навигации
откройте свежий отчёт. Исправление реакций применяется к новым событиям;
после перезапуска история не рассылается заново. Текстовые ответы и личные напоминания
этим механизмом не повторяются. Длительная недоступность прокси может помешать реакции
даже после трёх попыток, но дейлик сохраняется до обращения к Telegram.

Образы `v1.2.1` оставьте до завершения проверки обновления. Теги `current` и `v1.2.2`
с одинаковым IMAGE ID обозначают один образ и не занимают место дважды.
